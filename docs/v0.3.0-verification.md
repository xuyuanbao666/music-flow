# v0.3.0 verification checklist

The existing Web client keeps its data model and browser test. A separate Flutter native client uses the libmpv audio engine and an app-managed local music library. Both interfaces use the new violet design, rather than shipping a WebView disguised as a native player.

| Target | Candidate output | Verification |
| --- | --- | --- |
| Web | zip | existing production Chromium WAV smoke |
| Windows x64 | portable ZIP + Inno Setup EXE | real native WAV integration and release build |
| Linux x64 | tar.gz + DEB | real native WAV integration under Xvfb + PulseAudio null output |
| macOS | unsigned DMG | native WAV integration and release build |
| Android | debug-key-signed universal APK | Android emulator WAV integration, APK release build |
| iOS | simulator app ZIP | iPhone simulator WAV integration and simulator build |

All candidate artifacts include verified SHA-256 sums. Do not treat CI artifacts as releases. Windows MSI/AppImage, production Android signing, macOS notarization, Apple device IPA signing, real-device/lock-screen tests, tag/cover extraction, native lyrics, cloud sync, and dependency-license redistribution review are separate release gates. Flutter dependency lockfile must be committed following successful resolution. No release job for v0.3.0 is enabled at this stage.
